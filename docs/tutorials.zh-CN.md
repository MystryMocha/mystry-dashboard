# 分步教程

[English](tutorials.md) · **简体中文**

以下教程按步骤覆盖最常见的使用场景。尚未安装面板时，先阅读 [快速开始](getting-started.zh-CN.md)；各页面与字段的完整说明见 [使用指南](user-guide.zh-CN.md)。

---

## 教程 1：第一次开服（推荐 Paper）

适合：首次在本机使用面板，希望快速开设一个好友可加入的小型服务器。

### 1. 装好 Java

Minecraft 服务端依赖 Java，但无需提前安装：部署或导入服务端时，面板按游戏版本自动选中已安装的合适 Java；若没有，则显示 **「安装 Java N」** 按钮。在 Windows 与 Linux（x64）上点击该按钮，面板即下载 Eclipse Temurin，校验后安装并选中。

如需自行安装，按目标游戏版本选择对应的 Java：

| 游戏版本 | 所需 Java |
|---|---|
| 26.1 及以上（年份版本号） | Java 25 |
| 1.20.5 – 1.21.x | Java 21 |
| 1.17 – 1.20.4 | Java 17 |
| 1.16.5 及更早 | Java 8 |

安装后可在命令行运行 `java -version` 确认。电脑上可同时安装多个 Java，部署时在面板中选择即可。

### 2. 启动面板并登录

1. 启动面板：
   - **便携版（推荐）**：解压后，Windows 双击 `mdash.cmd`。面板在后台运行，窗口中显示账号与重要日志；关闭窗口不影响面板和服务端，如需停止面板，再次双击打开窗口并按 `Ctrl+C`。Linux 在解压目录中运行 `./mdash start`。无需安装 Node.js。
   - **源码版**：先安装 Node.js 22 或更高版本。Windows 双击仓库根目录的 `mdash.cmd`；Linux / WSL 运行 `./mdash.sh start`。首次运行自动安装依赖并构建，耗时数分钟。
2. 启动器自动生成配置并打开浏览器；若浏览器未自动打开，手动访问 `http://127.0.0.1:3000`。
3. 首次启动时，启动器自动创建管理员 `admin` 与随机密码，并显示在启动窗口中。密码仅显示这一次，须当场记下。
4. 页面显示「登录面板」后，填入窗口中的用户名与密码，点击「登录」。
5. 登录后，点击左下角齿轮进入「面板设置」，点「修改密码」设置自己的密码（至少 12 个字符）。忘记密码时，在面板运行期间执行 `reset-password` 命令（如 Windows 上的 `.\mdash.cmd reset-password`），窗口将显示新密码。

不要将密码、配置文件或含有它们的截图发给他人。如需手动编写配置或以开发模式运行，见 [快速开始](getting-started.zh-CN.md#手动安装与首次配置)。

### 3. 一键部署 Paper

1. 点击左侧的 **「一键部署」**（尚无实例时，也可点击实例总览页中央的 **「一键部署」**）。
2. 页面已默认选中 **Paper**（推荐新手使用，支持插件）与最新正式版游戏版本，通常只需处理以下几项：
   - **实例名称**：例如 `我的生存服`。
   - **游戏版本**：如需与好友使用其他版本，在下拉框中改选；客户端版本须与此一致。
   - **Java**：面板自动选中与游戏版本匹配的已安装 Java。若出现 **「安装 Java 21」**（或其他版本）按钮，点击并确认，等待安装完成（下载期间可取消），完成后自动选中。所用 Java 与推荐版本不一致时，无法点击「开始部署」。下载失败时，将下载来源切换为国内镜像后重试，或按 [第 1 步](#1-装好-java) 自行安装。
   - 勾选 **「我已阅读并同意 Minecraft EULA」**，否则无法开始部署。
3. **Paper 构建版本**、内存与优化方案保持默认即可：构建版本留空时使用最新构建（优先稳定版），内存按电脑总内存自动推荐。
4. 点击 **「开始部署」**，等待进度条达到 100%。任务可能先排队，页面持续显示状态直至完成或失败，请勿重复提交；也可离开页面，在右上角「任务中心」查看进度。
5. 完成后自动跳转至该实例页面。实例文件由面板统一存放于数据目录的 `instances` 文件夹，安装位置无需也无法选择。

> Forge / NeoForge 的部署步骤类似，但须下载官方安装器并执行安装，耗时更长，见 [教程 4](#教程-4部署-forge-或-neoforge-模组服)。

### 4. 启动服务端

1. 在实例页顶部点击 **「启动」**。
2. 切换到 **「控制台」**，等待出现类似 `Done (xx.xxxs)! For help, type "help"` 的输出。状态徽章显示「运行中」仅表示进程已启动，出现 `Done` 后方可进服。
3. 若控制台提示 Java 版本不符（如 `UnsupportedClassVersionError`），回到 [第 1 步](#1-装好-java) 安装对应的 Java，再在「实例设置」中选中它。

### 5. 本机进游戏测试

1. 打开 Minecraft，版本须与 **游戏版本** 一致（Paper 服以对应版本的原版客户端进入）。
2. 多人游戏 → 添加服务器 → 地址填 `127.0.0.1` 或 `localhost`。
3. 若无法连接，在 **「参数配置」** 页检查 `server-port`（默认 25565），并确认该端口未被本机其他程序占用。
4. 若进服时提示不在白名单中，说明服务端开启了白名单（Paper 26.3 首次启动即会开启）。可在控制台执行 `whitelist add 玩家名` 将自己加入名单；不需要白名单时，在「参数配置」关闭「启用白名单」并重启。白名单开启而名单为空时，控制台上方与「联机」页均有提示。

### 6. 让朋友联机（同一局域网）

1. 在 **「参数配置」** 页确认 `online-mode=true`（正版验证），或按需修改。
2. 打开侧栏的 **「联机」**，选择该实例。**「直接连接」** 中显示加入地址（如 `192.168.1.100:25565`），点击 **「复制」** 后发给好友。
3. 好友在游戏中添加服务器，填入该地址。

好友不在同一 Wi-Fi 或路由器下时，在联机页改用 **「虚拟局域网」** 或 **「frp 穿透」**，步骤见 [使用指南：联机](user-guide.zh-CN.md#联机)。

## 教程 2：导入已有的 zip 服务端

适合：已从别处下载完整的服务端包，或自行打包了 `server.jar` + 配置 + 世界。

### 1. 准备 zip

- 格式：**ZIP**（不支持 RAR / 7z）。
- 大小：约 **512 MiB** 以内，且不超出 ZIP 条目与解压配额。
- 内容：应包含可运行的服务端 jar（面板自动探测，常见名称为 `server.jar`、`paper.jar` 等）。
- 若 ZIP 内仅有**一个顶层文件夹**（如 `myserver/server.jar`），导入时其内容自动「展平」至实例根目录。

### 2. 上传导入

1. 在侧栏打开 **「导入服务端」**，切换到 **「上传 ZIP 压缩包」**。
2. 点击选择区选取 ZIP 文件（也可将文件拖入），再点击 **「上传并检查」**。
3. 预检通过后，在右侧 **导入设置** 中填写 **实例名称**。ZIP 的核心与版本须到导入时才能识别，因此摘要显示「导入时自动识别」，并提示暂无法确认 Java 是否合适；若已知版本，点击 **修改设置** 填写核心与 Minecraft 版本，面板即按版本推荐 Java。
4. 若检测到 `user_jvm_args.txt`，面板自动沿用其中的参数，摘要的内存一栏显示「来自 user_jvm_args.txt」；如不需要，在 **修改设置** 中点击提示后的 **取消**。解析失败时不予沿用。
5. 如有需要，在 **修改设置** 中修改 Java 运行时与 JVM 优化方案；若包内尚无 `eula=true`，勾选 EULA。
6. 点击 **「确认设置并导入」**，等待后台任务完成。队列已满时预览保留，可稍后再次确认。

实例目录由面板自动分配，无法指定。预检结果保留 30 分钟，在同一标签页刷新后仍可继续确认；取消、过期或面板重启时，上传的临时文件将被删除。

### 3. 导入后检查

1. 进入实例的 **「实例设置」**，确认 **Jar 文件名** 与目录中的实际 jar 一致。模组服的 jar 未必名为 `server.jar`，以探测结果为准。
2. 在 **「文件管理」** 页检查 `mods`、`config` 等是否完整。
3. 点击 **「启动」**，在控制台查看日志；若报 Java 版本错误，按 [教程 1 第 1 步](#1-装好-java) 安装匹配的 Java，再在「实例设置」中重新扫描并选中。

## 教程 3：改端口、难度与可见性（server.properties）

1. 进入实例 → **「参数配置」** 标签页。
2. 常用设置：
   - `server-port`：监听端口（修改后须重启实例）。
   - `max-players`：最大玩家数。
   - `difficulty`：`peaceful` / `easy` / `normal` / `hard`。
   - `gamemode`：`survival` / `creative` 等。
   - `white-list`：为 `true` 时仅白名单玩家可加入（须在控制台执行 `whitelist add <玩家名>`）。
   - `online-mode`：是否启用正版验证。
3. 修改后点击 **「保存配置」**。
4. 在实例页点击 **「重启」** 使配置生效（面板会提示修改后须重启）。

也可在 **「文件管理」** 中直接编辑 `server.properties`，效果与「参数配置」页相同。

## 教程 4：部署 Forge 或 NeoForge 模组服

1. **「一键部署」** → 核心类型选 **Forge** 或 **NeoForge**。
2. 选择 **游戏版本**，再选对应的 **Forge / NeoForge 版本**（Loader 下拉框）。
3. 页面会提示须先下载官方安装器并完成安装，**耗时比其他核心长**，请保持网络畅通。
4. 部署完成后，在 **「文件管理」** → `mods` 文件夹中上传模组（须先 **停止** 实例）。
5. 启动后若缺少依赖，控制台会报错；按模组说明补装依赖，或改用兼容版本。

所需 Java 版本与原版相同，见 [教程 1 第 1 步](#1-装好-java)。

## 教程 5：用控制台管理玩家与权限

在实例的 **「控制台」** 中输入命令，按 **回车** 发送（与游戏内控制台相同）。

| 目的 | 示例命令 |
|------|----------|
| 授予玩家管理员权限 | `op 玩家名` |
| 踢出玩家 | `kick 玩家名` |
| 保存世界 | `save-all` |
| 白名单 | `whitelist on` / `whitelist add 玩家名` |
| 查看帮助 | `help` |

控制台保留最近的输出，刷新页面后先显示这些历史输出。

## 教程 6：上传地图或插件

### 上传文件到实例目录

1. **停止** 实例（修改世界或大型文件前，建议先停服）。
2. **「文件管理」** 标签页 → 进入目标目录（如 `world`、`plugins`、`mods`）。
3. 点击 **「上传」**，选择本地文件。
4. **「新建文件夹」** 用于创建子目录。
5. 文本文件（如 `ops.json` 与部分配置文件）可点击文件名，或点击右侧「…」菜单中的 **「编辑」**，在线修改。
6. 完成后点击 **「启动」** 或 **「重启」**。

文件页仅能操作当前实例的根目录，并非全盘文件管理器。

### Paper 插件

- 将 `.jar` 插件放入 `plugins` 目录（须使用 Paper 核心，而非纯 Vanilla）。

## 教程 7：管理多个实例

1. **实例总览** 列表每 5 秒自动刷新状态。
2. 每个实例拥有独立的进程与端口（在各自的 `server.properties` 中配置，**不得让两个实例共用同一端口**）。
3. 在总览中可 **启动 / 停止 / 重启 / 删除** 实例：
   - **删除** 前须确认，随后删除该实例在面板托管目录中的全部磁盘文件，不可恢复。
   - 运行中的实例须先 **停止**，方可删除。
   - 面板不会访问或删除旧版外部目录。
4. 侧栏底部可 **「退出登录」**；登录状态保存在当前浏览器中。

## 教程 8：备份与迁移

### 备份

如只需备份单个服务器的世界与文件，使用实例页的 **备份** 分段即可，运行中亦可一键备份与还原；开启 **每天定时备份** 后每日自动备份，并只保留最新的若干份，见 [使用指南 - 备份](user-guide.zh-CN.md#备份)。整个面板（含账号与实例设置）的备份方法如下。

先正常停止所有 Minecraft 实例，再通过当前使用的管理器停止面板并确认其已退出，然后复制数据。在运行中直接复制世界文件或 SQLite 数据库，可能得到不一致的备份。

建议复制完整的数据根与当前入口所用的配置文件（见 [配置说明](configuration.zh-CN.md)），至少保留以下内容：

- `DATA_DIR/panel.db`（实例列表与设置）
- 每个实例的 `DATA_DIR/instances/<id>/` 完整目录

若停止后仍有 `panel.db-wal` 或 `panel.db-shm`，随数据根一并保留，不要手动删除。备份含账号与密钥，应存放在访问受限的位置；恢复前先备份当前数据，并以独立副本演练。

### 在同一台机器恢复

1. 停止面板进程。
2. 还原 `panel.db` 与 `DATA_DIR/instances/<id>/`，保持相同的 `DATA_DIR` 和实例 ID。
3. 启动面板并检查实例列表；必要时在实例页执行 **完成迁移**。

### 接管面板外已有服务器

先在原服务器控制台执行 `stop`，再按 [上传文件夹](user-guide.zh-CN.md#上传文件夹) 将其复制为面板实例；面板不会删除原目录。

### 从旧版外部目录迁移

按 [旧版外部实例接管](user-guide.zh-CN.md#旧版外部实例接管) 操作：停止实例与面板，完整复制旧目录，再点击 **完成迁移**。

### 仅迁移世界

可在实例的 **文件管理** 页下载 `world` 中的单个文件；如需复制整个目录，先停止实例（必要时一并停止面板），再用系统工具复制托管实例目录下的 `world`。
